Native Linux filesystem · Experimental

LLM memory
and context.

Our goal: a filesystem where LLM-based agents can retain memories across sessions and retrieve them as context. We are building the storage foundation, starting with shared, immutable content.

Reproduce the experiment →Explore the code ↗

Implemented today: read-only M1. Image creation, native mounting and shared reads are tested in a Linux VM. Agent memory retrieval, context assembly, writes and transactions are not implemented.

The goal: persistent memory for agents.

Keep observations, decisions and task records available beyond a single conversation.

MoobFS aims to store and expose those memories as files, share repeated content and eventually preserve revisions. Agents could retrieve that material to build context for later tasks.

See the proposed next steps →

Storage and context have distinct roles

The filesystem stores and exposes memory. The agent application selects what is relevant and assembles the context sent to the LLM.

Semantic retrieval and agent integration still need to be designed and tested. MoobFS does not currently assemble prompts or extend a model's context window.

The working M1 prototype below validates shared storage. It is the first step toward this goal.

Shared content.
Independent files.

Sharing bytes is a storage decision. Each file keeps its own identity.

The image creator groups identical content into one object. The kernel module resolves ordinary file reads to that object's blocks. Both paths work through the Linux VFS.

A small experiment with observable results

The test opens both files, compares their bytes and checks FIEMAP. Different inode numbers, link count 1, the same physical extent and the SHARED flag.

No speedup claims yet. Metadata and alignment still take space, and disk sharing does not automatically share every page in memory.

Run it.
Inspect the evidence.

One command builds the module and boots a disposable QEMU VM with a matching Linux kernel. Docker supplies the tools; the host kernel stays outside the experiment.

Native test instructions →
git clone https://github.com/studiomoob/llmoobfs.git
cd llmoobfs
make vm-test

Requires Docker. Tested with Linux 6.12.111+deb13-amd64. Logs, image metadata and environment details are written to build/vm/.

  1. VALIDATED · M1

    Mount and share

    Immutable images, independent inodes, shared reads and malformed-image checks.

  2. PLANNED

    Harden the foundation

    Kernel sanitizers, fuzzing, concurrency and broader lifecycle testing.

  3. PROPOSED · M2–3

    Publish and retain

    Durable writes, crash recovery, revisions and snapshots with explicit compatibility.

  4. PROPOSED · M4

    Evaluate with agents

    Measure memory utility, storage cost and latency against defined baselines.
